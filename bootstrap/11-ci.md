# Módulo 11 — CI/CD: o gate real

## Depende de: 10

## Objetivo
Hooks locais são **burláveis** (`git commit --no-verify`). A verdadeira trava é o CI, que roda os **mesmos** checks de forma inescapável e bloqueia o merge.

## Entregáveis obrigatórios

### 1. `.github/workflows/ci.yml` (adaptar ao provedor de CI dos parâmetros)
```yaml
name: CI
on: { pull_request: {}, push: { branches: [main] } }
jobs:
  quality:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }            # gitleaks precisa do histórico
      - uses: actions/setup-node@v4         # ou setup-python/go conforme stack
        with: { node-version: '22' }
      - run: <install com lockfile frozen>  # ex.: npm ci / pnpm i --frozen-lockfile
      - run: <lint>
      - run: <typecheck>
      - run: node scripts/verify-rules.js   # MESMA trava do hook
      - run: <test --coverage>              # falha abaixo do threshold (módulo 12)
      - run: <build>
      - run: <secret-scan>                  # ex.: gitleaks/gitleaks-action
```
Regras:
- Instalação SEMPRE com lockfile congelado.
- O passo `verify-rules` é literalmente o mesmo comando do hook — nenhuma divergência entre trava local e remota.
- Secret scanning (gitleaks ou equivalente) como gate, não como aviso.
- Cobertura: o threshold será configurado no módulo 12; deixe o passo presente (pode passar sem threshold por ora, com `TODO módulo 12`).

### 2. Branch protection em `main`
Sem isso, todas as outras regras são opcionais na prática. Se houver acesso à API/painel do provedor: ativar **PR obrigatório + CI verde para merge + proibir force-push**. Se não houver acesso, entregar ao humano o checklist exato de cliques/comandos e marcar como pendência humana no MASTER-PLAN (não conta como ✅ do módulo até confirmado).

### 3. Badge/documentação
Referência ao workflow no README (módulo 15 finaliza; deixar nota).

## Regras invioláveis deste módulo
- CI roda exatamente os mesmos checks do pre-commit (paridade total) + os que só fazem sentido remoto (secret scan de histórico, build).
- Nenhum check do CI marcado como `continue-on-error`.

## Critério de aceite
- [ ] YAML válido (validador local ou `act`, se disponível; senão, lint de YAML + revisão passo a passo).
- [ ] Paridade confirmada: lista de comandos do hook ⊆ lista de comandos do CI.
- [ ] Branch protection ativada OU checklist entregue ao humano com pendência registrada.
- [ ] Se o repo já estiver num remoto: abrir PR de teste com violação plantada e confirmar CI vermelho; depois limpar. (Se não houver remoto ainda, registrar como pendência de primeira subida.)

## Ao concluir
1. Marcar ✅ na linha 11 do `MASTER-PLAN.md` (ou 🟡 com a pendência humana explícita).
2. Entrada no `DECISIONS.md`.
3. PARAR. Não iniciar o módulo 12 nesta mesma resposta.

## Cláusula anti-simplificação
Nenhum item dos Entregáveis é opcional. Antes de encerrar, liste cada entregável e seu status. Se algo ficou de fora, o módulo NÃO está concluído.
